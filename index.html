  2. 2025AI-powered semantic commit generation. Creator and architect.

    SemiGit

    A VS Code extension that decides when a commit is due and writes it. Fully offline by default.

    Read the docs

    Problem

    Git history is noisy (“wip”, “fix”, “final2”) because commits happen when a developer feels done, not when a unit of work is. Existing tools format messages; none decide when a commit should happen or what it represents.

    Approach

    A local-first extension that watches your session, diffs code structurally with the TypeScript Compiler API, scores feature-level milestones and writes the Conventional Commit. Five optional AI providers (OpenAI, Claude, Gemini, DeepSeek, Ollama) sit behind one interface.

    Result

    One universal .vsix with SQLite in WebAssembly and no native modules, 90+ tests on a three-OS CI matrix, and output quality measured against real git history by a backtest harness.

    Built with TypeScript, VS Code extension API, TypeScript Compiler API, multi-provider LLM, SQLite on WASM, Conventional Commits.

  6. 2026Secure offline payment simulation over mesh networking. Backend engineer.

    Offline UPI Mesh

    Payments that survive losing the network: encrypted packets hop device to device until one reaches the internet.

    Read the docs Source on GitHub

    Problem

    Digital payments fail completely without internet access, a real gap in low-connectivity regions.

    Approach

    A Spring Boot backend that simulates offline UPI payments. Each transaction is encrypted (RSA and AES-GCM), wrapped in a TTL-bound mesh packet and gossiped device to device until a bridge device with internet relays it to the server for settlement.

    Result

    An end-to-end, cryptographically secure payment flow that survives total network loss on the sender’s side, with gossip-based packet propagation.

    Built with Java, Spring Boot, RSA and AES-GCM, mesh networking, gossip protocol.

  8. 2026Regression gate for AI agents. Creator and maintainer.

    Fisherman

    CI for LLM agents. It tells a real regression from noise before you merge.

    Source on GitHub

    Problem

    Agents break silently. Changing a prompt, swapping a model or editing a tool can shift behaviour, and unit tests can’t say whether things got worse because agent behaviour is probabilistic and multi-turn.

    Approach

    Replay the same eval suite on the old and new version, then let statistics decide. McNemar’s exact test sets the verdict and a paired bootstrap reports the effect size. Cases mix deterministic rules with an LLM judge that is itself scored against a human-labelled set. Simulated users with hidden goals, including adversarial ones, test multi-turn behaviour.

    Result

    A merge gate that exits 2 on a significant regression, runs in GitHub Actions and works with any LiteLLM provider. Runs are traced with OpenTelemetry into SQLite, a read-only dashboard computes the same verdict as CI, and an offline suite of 359 tests needs no API keys.

    Built with Python, OpenTelemetry, SQLite, LiteLLM, FastAPI, McNemar and bootstrap statistics, GitHub Actions.

  9. 2026Autofill for job portals. Solo developer.

    LazyForm

    A Chrome extension that fills job applications from a profile you save once.

    Source on GitHub

    Problem

    Every job portal asks for the same name, work history and “Are you authorized to work?” answer, and every portal words and lays them out differently.

    Approach

    You save a profile once. On an application the extension reads each question from its label, ARIA text, placeholder and section heading, works out what it asks, and fills it. Auto-apply mode carries on through every step and page until you press Stop. It never submits, never ticks consent boxes and never overwrites what you typed.

    Result

    A Manifest V3 extension where all data stays in the browser, with no server and no network calls. 111 Playwright checks run the real extension in Chromium against Greenhouse-, Lever- and React-style forms, multi-step pages and a hostile page.

    Built with JavaScript, Chrome Manifest V3, chrome.storage, Playwright.

  10. 2026Priority-aware fleet allocation. Solo developer.

    Dispatch LoadBalancer

    A REST service that assigns delivery orders to vehicles by priority and capacity, and plans short routes.

    Source on GitHub

    Problem

    Orders have priorities and weights, vehicles have capacities and positions, and the fleet can’t carry everything. Higher-priority orders must win, and nothing may exceed a vehicle’s capacity.

    Approach

    Orders are placed HIGH, then MEDIUM, then LOW onto the vehicle and route position that adds the least Haversine distance. A bounded swap pass trades one order for unassigned ones that fit, and 2-opt shortens each route. The optimizer is pure and deterministic, so the same data always gives the same plan.

    Result

    On the official 30 orders and 5 vehicles it places all 12 HIGH, all 8 MEDIUM and 4 of 10 LOW orders, filling every vehicle to capacity, and lists the 6 it can’t carry with a reason. 16 unit and 6 PostgreSQL integration tests pass.

    Built with Java 21, Spring Boot 3.5, PostgreSQL 16, Flyway, springdoc (Swagger UI), JUnit 5, Docker Compose.
