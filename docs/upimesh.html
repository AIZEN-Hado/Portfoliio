Offline UPI Mesh

Secure Offline Payment Simulation over Mesh Networking

Java 17 Spring Boot RSA + AES-GCM Gossip Protocol H2 In-Memory DB Maven Wrapper
A Spring Boot backend simulating offline UPI payments using mesh networking + cryptographic security.

Concept Overview

Digital payments fail entirely without internet connectivity. Offline UPI Mesh demonstrates how a payment created on an offline device can still reach settlement — encrypted end-to-end and relayed device-to-device until any one device in the mesh has connectivity.

Problems & Solutions

Untrusted Devices

A stranger's device relays your payment packet.

Solution — Encryption. Intermediate devices cannot read or modify the payload; they only forward ciphertext.

Duplicate Transactions

Multiple bridges upload the same packet to the backend.

Solution — Idempotency. Hash → Atomic Check → Only 1 Processed.

Replay Attacks

An old packet is captured and re-sent later.

Solution — timestamp validation ⏱️ and a unique nonce per transaction 🔑.

How to Run

# Windows
mvnw.cmd spring-boot:run

# Mac/Linux
./mvnw spring-boot:run

Then open http://localhost:8080.

Demo flow

1

Inject Payment

Create an encrypted payment on the (simulated) offline sender.

2

Run Gossip

Propagate the mesh packet device-to-device.

3

Bridge Upload

A connected bridge device flushes packets to the backend.

4

Settlement

The backend deduplicates, decrypts, validates, and settles into the ledger.
